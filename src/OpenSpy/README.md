# qDNSmOpenSpy

`qDNSmOpenSpy.sprx` applies the OpenSpy runtime patch to a supported game. It is
not a boot plugin. The main plugin loads it from
`/dev_hdd0/plugins/qDNSm_modules/` while a game is running, starts it with a
fixed request, and unloads it when the patch finishes.

## Boundary

The main plugin owns `paf`/`game_plugin` title lookup, `vsh::GetGameProcessId`,
game-exit detection, and the XMB notification. It passes:

- game pid
- the GameInfo and GetTitleId candidates
- a shared stop flag

`src/OpenSpy/OpenSpyProtocol.hpp` is the complete ABI; keep it plain C types and
fixed buffers.

`module_start` runs the scan and patch synchronously and sets `done` before it
returns. The scan threads are joined inside that call, so the module can be
unloaded immediately afterwards. `module_stop` only records that teardown ran.

## Layout

- `qDNSmOpenSpy.cpp` — module entry points
- `OpenSpyPatch.cpp` — scan/patch implementation
- `OpenSpyPatchPlan.cpp/.hpp` — patch-plan validation
- `OpenSpySupportedTitles.cpp/.hpp` — supported-title lookup
- `OpenSpySupportedTitles.generated.hpp` — generated by
  `tools/gen-supported-titles.py`
- `OpenSpyProtocol.hpp` — main/module ABI
- `OpenSpyWorker.hpp` — internal worker entry

The module has no `paf`, `vshmain`, or game-plugin imports, so it does not
depend on the main plugin's VSH hooks. It uses the same export-stub C++ runtime
and `sysPrxForUser` allocator pattern as `qDNSmNetLib`.

## Build

See the OpenSpy module build section in `AGENTS.md`. The build signs the PRX with
the same 3.55 homebrew key set as the other qDNSm modules.

`QDNSM_OPENSPY_LOGGING` is `0` for release. At `1`, diagnostics are appended to
`qDNSm-openspy.log` beside the module; leave it at `0` for shipping builds.
